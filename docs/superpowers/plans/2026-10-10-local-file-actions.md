# 附件与本地文件操作实现计划

**目标：** 附件可在本机直接打开或定位；本地文件引用直接使用原文件，界面说明两者区别。

**架构：** 保留已有 file 卡片，增加 `localFile: true, filePath` 子类型。打开接口只接受已保存的任务和卡片标识以及 `open/reveal` 操作，由后端解析目标；MCP 仅保存路径引用，不主动打开文件。附件使用带扩展名的内部存储路径，旧无扩展名文件按需复制并保留，后续读取始终优先同一个新路径。

**技术栈：** 原生网页、Node.js、Windows PowerShell 5.1、现有 MCP SDK。

**验收记录：** 完整回归 41 项通过。独立审查补充了 Windows 特殊扩展名和逗号路径边界，两处均先复现失败再修复；修改后相关测试再次通过。浏览器正常按钮实测原文件默认程序打开、附件定位与前台确认、路径刷新保留、画布和列表入口。界面无控制台错误。本机服务已启动新版本，重启前后用户 state.json 的 SHA-256 一致。
